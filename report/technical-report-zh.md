# Common Ground / Leeds——补充技术报告

**字数：** 约 900 字

## 1. 问题概述

Common Ground / Leeds 是一个探索性 Web GIS 网站，用于展示利兹公共绿地的空间分布及其记录面积。电子表格或静态地点清单只能列出名称，不能直观表达城市范围内的空间模式，也不便于比较不同地点。因此，本项目将数据转化为交互式地图，使居民、学生和地方规划相关人员能够探索哪些绿地被记录、它们属于什么类型，以及哪些地点具有较大的记录面积。本项目是一个探索性原型，不把空间距离直接解释为步行可达性、场地质量、安全程度或健康影响的证据。

## 2. 需求与使用场景

作业简报要求使用 HTML、CSS、JavaScript 和 Leaflet 构建一个有效的网站，并配有解释性文字和规范的数据引用。基于这一要求，我将主要使用场景定义为：没有专业 GIS 软件和知识的访客，也能够理解项目目的、查看利兹整体绿地分布、搜索地点名称、按类型筛选、比较记录面积，并查看单个地点的详细信息。

因此，网站包含叙事式介绍、Leaflet 地图、分类选择器、不区分大小写的名称搜索、地点弹窗、重置操作、统计摘要、类别构成条形图、记录面积最大的五个绿地列表，以及“按类型/按面积”的地图强调模式。点击类别图表中的名称会同步更新地图和筛选器；点击排名列表中的地点会把地图移动到对应空间、突出显示该空间并打开弹窗。页面还加入数据来源、局限性说明、键盘焦点样式、响应式布局和减少动画模式。

## 3. 数据与方法

数据来自 Leeds City Council 的 Public Green Spaces ArcGIS REST 要素服务。该服务每次最多返回 1,000 条记录，因此使用两次分页请求获取完整的 1,781 条记录。请求时将几何数据转换为 WGS84，以便 Leaflet 直接使用。本地 GeoJSON 保留地点名称、来源编号、行政区域、记录面积、所有权和维护方字段，同时依据服务字段元数据将原始类型编码转换为可读的分类名称。分类不是根据地点名称主观推断的；缺失的可选字段统一显示为“Not available”。

浏览器只加载一次本地 GeoJSON。JavaScript 保存完整数据，并根据分类和搜索词生成当前筛选结果。每次筛选后，Leaflet 重新绘制可见的 GeoJSON 图层。统计摘要也根据当前可见数据重新计算，包括地点数量、不同分类数量和已知记录面积之和。

地图包含两种视觉模式。“Types”模式使用统一的苔藓绿色显示空间；“Area”模式使用由浅到深的绿色顺序编码，将记录面积分为小于 5 公顷、5 至 20 公顷和超过 20 公顷三档，缺失面积使用单独的浅色处理。这种颜色表达的是记录面积大小，而不是场地质量。地图图例解释了面积阈值，编号标记显示记录面积最大的五个多边形空间。地图上的编号与下方排名列表相互对应，为用户提供两种访问相同信息的方式。

## 4. 技术选择与设计理由

语义化 HTML 提供标题、标签、列表和页面地标。CSS 使用暖米白、深绿色、少量琥珀色、衬线标题字体和响应式不对称布局，形成编辑风格。选择原生 JavaScript 是为了让课程要求中的编程过程清晰可见，也避免让外部图表框架成为项目主体。Leaflet 能够以较小的客户端开销支持底图、GeoJSON 样式、弹窗、范围缩放和地图控件，因此适合本项目。

网站通过 GitHub Pages 以静态文件形式部署，当前范围不需要身份验证、数据库凭据或服务器端代码。弹窗内容在插入页面前进行 HTML 转义。网站不收集姓名、位置或其他用户提交的数据，仓库中也没有 API 密钥。

## 5. 问题、局限性与未来工作

主要技术问题是 ArcGIS 服务的单次记录限制，已通过分页请求解决。第二个问题是类型字段使用缩写编码，已通过检查服务字段元数据后再进行标准化处理。由于多边形数量较多，城市整体视图可能较密集，因此网站提供筛选、面积强调、透明度和排名导航，而不声称所有形状在所有缩放级别下都同样清晰。

数据记录的是地图空间，而不是当前实际的进入条件。它不能证明出入口、步行时间、坡度、维护情况、主观安全感、使用人数或无障碍条件。记录面积是来源数据中的属性，不能等同于独立测量的可达性或生态指标。服务元数据没有明确说明独立图层许可，因此正式公开发布时仍应遵守 Leeds City Council 的开放数据条款。

未来可以加入五分钟、十分钟和十五分钟步行网络分析，比较人口和贫困数据，记录出入口与设施，加入数据更新时间，并自动检查市议会数据是否发生变化。也可以提供可访问的数据表下载，并在比较不同行政区时避免把相关关系解释为因果关系。
